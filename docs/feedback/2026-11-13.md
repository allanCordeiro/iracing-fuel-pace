# Feedback 2026-11-13 (build 0.1.0+50.302c30c, debug zip)

Five bundles (2026-11-10 and 2026-11-13; the last one a 30 min race against other cars, Ligier JS P320 at Motegi). No errors
or warnings in the logs. The driver saw no visual impact; two stutters, without marks, could not be tied to the app (tick p99
20–60 µs, a 15–16 ms tick only when a session starts, on the telemetry thread; a few gen0 GCs per minute).

## 1. PresentMon script did not run

`presentmon.ps1 -PresentMon ... -Label sem` in an elevated PowerShell: "O termo 'presentmon.ps1' não é reconhecido". Causes: PowerShell
runs a script of the current folder only as `.\presentmon.ps1`; the script is inside the app zip, not in the downloaded artifact
folder; and Windows' default execution policy blocks scripts anyway. Fix: `-PresentMon` is optional (the script looks for
`PresentMon*.exe` next to itself, then in Downloads) and warns when not elevated or iRacing is not running; LEIA-ME section 11
rewritten as copy-paste steps with `powershell -ExecutionPolicy Bypass -File .\presentmon.ps1 -Label sem|com`.

## 2. Perfis: the captures of the selected profile never showed

Log: `GetProfile` at 00:40:13.940, then `ListProfiles` 14 ms later. `ProfilesViewModel.OnProfile` asks for the list again (counts
changed); in `OnList`, `Items.Clear()` makes WPF's ListBox drop the selection through the two-way binding, and
`OnSelectedItemChanged` cleared the captures (without asking for them again, since the list was loading). The view-model tests
never saw it: without a ListBox nothing nulls the selection. Fix: a selection change during the list reload does nothing; the
captures are cleared only when the selected profile is gone from the list. Test: `Captures_stay_when_the_list_is_refreshed`
(simulates the ListBox).

## 3. Captura: "iRacing não está conectado" while iRacing was running and capturing

Log: the Settings window connected (Hello) at 23:35:28, the session started at 23:38:16. The Agent sent the snapshot only as the
answer to Hello; nothing told an open window that the sim connected or the session changed. Fix: new IPC message
`SessionChanged` (sim connected, profile key, car, track, session type, tank), broadcast by the Agent on connect, disconnect, a
new session info whose fields changed, and a session number change; only when a field changed. Tests:
`Session_changes_reach_an_open_settings_window` (Agent), `Session_changes_update_the_line_and_the_finished_capture_can_be_edited`
(Settings).

## 4. Dados por volta: Incluir / Excluir not clickable

Same cause as 3: without the profile key, `CaptureViewModel.OnFinished` ignored the `CaptureFinished` (its key did not match a
null one), the capture id was never set, and the actions stayed disabled. Fixed by 3. While a capture runs the actions stay
disabled by design (the capture is saved when it stops); the link now says so in a tooltip.
